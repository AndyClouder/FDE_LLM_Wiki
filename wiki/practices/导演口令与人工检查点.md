# 导演口令与人工检查点

## 核心打法
多技能工作流用一段"导演口令"指挥——说清顺序、中间产物、暂停点;**技能做执行,人做决策**:"让技能各做各的事,让人来做决策。"

## 操作步骤
1. **一个技能只做一件事**:万能技能三痛点(好能力被锁死在一个技能里 / 中间环节缺人的把控 / 出问题不知道找谁);判断该不该独立两问:输出是不是完整有独立价值的交付物?某个步骤会不会在别的场景被单独使用?
2. **三种组合**:串联(A 的输出文件 = B 的输入,流水线,中间可检查半成品)/ 并联(同素材多方案择优)/ 循环(**触发者是人不是技能**——B 输出成品 + 报告,人看报告决定是否打回 A)
3. **导演口令要素**:顺序、中间产物、暂停点;并联末句"你只给我三份文件的**文件路径和每份的一句话摘要**"——不加这句,子智能体会把三篇全文返回塞满窗口
4. **传数据三方式**:文件路径(大块数据)/ 上下文共享(短对话)/ 格式约定(A 输出 outline-x.md,B 读它);最佳实践:**"提示词传决策和方向,文件传数据和内容"**
5. **子智能体四要素**:目标、约束、输入、**验收**(大多数人第一次会忘写验收——没有自检条件,子智能体不知道做得够不够好);子智能体独立上下文、过程隔离、可并行,是上下文快满时的优雅解法;简单规则:一个上下文能搞定的事,别派子智能体
6. **文件两条规矩**:产出与输入放同一目录(中间产物聚在一起,一眼看清工作流脉络);同名文件先备份再覆盖
7. **四周演进路径**:第 1 周最小可用(两个技能串联)→ 哪个环节成瓶颈再有针对性地加——"先跑通,加一个,再跑通"

## 验证案例
写作工作流五技能(素材分析→大纲[等待用户选择]→写作→润色→配图):一篇科技评论从三四小时缩到四十分钟,**省下的不是思考时间,是体力活**;定选题、判断方向、终审把关留在人手里。

## 适用信号
- 自动化项目设计:人工检查点 = [[承诺与推进]] 在系统设计中的映射——关键决策点必须留人
- 中间产物文件化 = 可审计的交付痕迹,出问题能定位到环节(责任边界)
- 三个真金白银的坑:一开始搭完整版 / 子智能体返回全文 / 润色技能改了风格

**第二轮补入(2026-08-20)**:
- **技能互调:写死名字还是描述能力?**——问自己"把目标技能换成同类另一个,我的技能还能正常工作吗?"能 → 描述能力;不能 → 写死名字;倾向描述能力,强依赖特定行为才写死
- **工业级全自动循环**:把质检拆成独立技能(**只列问题、不动手改**),质检结果自动触发打回——节点多、搭建成本高,适合企业级内容审核等硬性标准场景;人肉循环仍是默认(循环触发者是人)
