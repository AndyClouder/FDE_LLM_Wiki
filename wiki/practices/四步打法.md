# 四步打法:从业务理解到结果验证

## 核心打法
FDE 团队进入客户现场后,**不马上写 Prompt 或搭 Agent**,先摸清业务;用四步把 Demo 推向生产。核心原则:**卖成果,不卖软件**——客户为业务真的变好付费,不为"用了 AI"付费。

## 操作步骤
1. **业务理解**:摸清客户的钱从哪里来、业务卡在哪里、AI 能从哪个环节撬动价值;行业业务专家参与,把 SOP、知识库、业务链路和关键指标梳理清楚
2. **协作搭建**:业务专家和 FDE 一起把场景转化为 Agent / 工作流 / 应用原型,不由技术人员一人硬扛
3. **工具保障质量**:从真实聊天记录、历史工单、业务数据中**生成测试集**,进行自动评测和 A/B 测试
4. **业务结果验证**:AI 组与人工组逐环节对比,用触达率、响应率、转化率、人效等指标说服客户继续投入

## 验证案例
腾讯云教育行业工作营即此模式变体:从教师真实教学任务出发选场景、拆流程、形成初版应用,再用课堂/教研/作业实践验证效果,最终孵化出行业产品 LearnBuddy。

## 适用信号
- 项目一开始就有人想直接搭 Agent / 写 Prompt
- 测试集是"拍脑袋"样例而非真实业务数据
- 验收标准是"功能可用"而非业务指标改善
