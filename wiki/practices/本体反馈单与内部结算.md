# 本体反馈单与内部结算

## 核心打法
用**标准化反馈格式 + 经济机制**让一线经验自动回流,破解"沉淀永远排在交付后面"。核心逻辑:让 Delta 有动力把现场发现传回 Echo(反馈可抵扣成本),让 Echo 有动力保持资产质量(质量差就没人用,内部"收入"归零)。

## 操作步骤
1. **反馈标准化**:每条反馈五要素——发现名称 / 客户场景 / 当前本体状态 / 改进建议 / **通用性判断**(预估多少比例客户有同类需求)
2. **评审分级**:A级(高通用高价值)立即采纳下版本发布;B级积累 2—3 个客户验证后再采纳;C级(高度个性化)不纳入,建议客户定制
3. **内部结算**:Delta 使用本体/模板时记账(项目启动时评估"从零定制 vs 用本体+适配"的工时差);反馈被采纳按级别抵扣(A级 1.5 万 / B级 0.5 万);每季度结算,净额进入 Echo 团队预算
4. **绩效双轨**:Delta 考核"项目交付 85% + 经验积累 15%"(随成熟升至 20—25%);Echo 考核"本体/平台质量 70% + 前线支持 30%"
5. **变更节奏**:不逐条改本体,每月批量评审 + 版本发布;区分"核心路径"(全客户共用)与"扩展点"(可选插件)

**认证四层与考核三类指标**(2026-08-20 第二轮补入,§8.6):
- 认证走"准入—跟项目—独立交付—经验积累—晋升分层"线,光统计上课次数没有意义:**准入认证**(独立完成小型 Agent 原型+讲清业务目标与风险边界)→ **项目认证**(跟随真实项目完成模块交付+测试样例+复盘记录)→ **独立交付认证**(需求澄清、方案设计、上线验证、客户沟通闭环)→ **Echo 候选认证**(高质量反馈多次被采纳+形成可复用 Skill/模板/行业方法)
- 考核三类指标:客户落地(按时上线/使用率/满意度/续费扩展)、工程质量(稳定性/权限安全/评测覆盖/故障响应)、经验积累(Skill 产出数/反馈采纳率/模板复用率/跨客户节省工时)
- **数据隐私产权三层表**:本体层=平台所有(实体/关系/行为规则抽象,不含客户真实数据)、客户 Skill=客户所有(访问客户数据的具体配置)、通用 Skill=平台所有(基于本体重新开发的通用能力模块)

## 验证案例
报告第九章 ERP 虚构案例:反馈单机制跑通后,本体从 V1.0 迭代到 V1.3,交付工时从 8 人天降至 4 人天;Delta 成员连续 3 个项目提交高质量反馈、2 次被 A 级采纳 → 进入 Echo 转岗评审。
(注:内部结算模型基于咨询方案设计,国内外尚无完整公开实施案例,参数需按组织实际调整。)

## 适用信号
- 一线做完项目没有利益驱动反馈后端(反馈链断裂)
- 考核只看项目是否交付,不考核知识资产贡献
- 团队"做完一个项目就清空,下一个完全重启"
