# 对话式反馈信号与反馈设计

## 核心打法
反馈是数据飞轮的燃料:**反馈嵌入工作流定点收集,用户直接编辑模型输出 = 最强偏好信号**;"User feedback is crucial... but if used indiscriminately, it can perpetuate biases and destroy your product."

## 操作步骤
1. **读自然语言反馈信号**:early termination(中途停止 = 对话不顺)/ **error correction**("No, I meant...";用户编辑输出 = 原输出输、编辑后赢,天然 preference data)/ complaints(FITS 八类:26.5% 重申需求、16.2% 答非所问、15.3% 指出可用搜索、11.3% 事实错…)/ sentiment(音量升高)/ refusal rate
2. **读行为反馈**:regeneration、会话删除(强负信号)/ 重命名、会话长度(客服场景长 = 低效;陪伴场景长 = 好)、对话多样性(长而重复 = 死循环)
3. **在三个时机收集**:开始时(校准,别制造摩擦)/ **出坏事时**(必须给降级出路:编辑 / 重生成 / 换模型 / 转人工)/ 低置信时(双响应对比选择 → 偏好数据)
4. **用工作流内控件**:Midjourney 四图三选项(upscale 最强正 / variation 弱正 / regenerate 全负);Copilot 灰色建议 + Tab 接受 / 继续打字拒绝;正向反馈谨慎(Apple:默认就该好,总问"满意吗"暗示好结果是例外;折中 1% 抽样)
5. **反馈偏差体检五类**:leniency(Uber 均分 4.8——星级通胀,解法:描述性选项替代数字)/ randomness(用户懒得读随机点)/ position(爱点第一个)/ preference(偏爱长回答)/ 曝光偏差
6. 反馈要附前 5-10 轮上下文才可诊断;别问用户答不了的问题(数学二选一不是偏好,要有"我不知道"选项)

## 验证案例
- Luma 愤怒表情放错位置,满意用户点出一星(UI 设计事故);私密反馈比公开更真实
- degenerate feedback loop 推演:少数用户爱猫图 → 系统多产猫图 → 吸引爱猫用户 → "猫的天堂"(同一机制可放大偏见);sycophancy:RLHF 模型倾向说用户想听的话(Sharma et al.)

## 适用信号
- 交付 AI 应用时把"反馈采集点"当功能设计,而非等客户投诉;客户现场的用户编辑日志就是最好的微调数据
