# 推理经济学与省钱四件套

## 核心打法
"No matter how good your model is, if it's too slow… its predictions might become useless." 投产前先做成本-延迟模型,再按"最有效四件套"优化——**推理占已部署 AI 系统 ML 成本最高 90%**。

## 操作步骤
1. **拆延迟**:总延迟 = TTFT(首 token)+ TPOT × 输出 token 数;TPOT ≈ 120ms(6-8 token/s)即达人类阅读速度,再快无感;看 p50/p90/p99 不看均值;Agent 场景用 **time to publish**(用户看到首字远晚于模型首字)
2. **非实时任务走 batch API(约 5 折)**:合成数据、定期报告、批处理、模型迁移重跑、大规模个性化、索引重建
3. **验收用 goodput 而非裸吞吐**:goodput = 满足 SLO 的吞吐(100 RPM 里只有 30 条达标,goodput 就是 30)——只看吞吐会做出差体验;警惕 **nvidia-smi 的 GPU utilization 是假指标**(真指标 MFU/MBU)
4. **最有效四件套**:量化 + tensor 并行 + replica 并行 + attention 优化;配套:speculative decoding(小 draft 生成大模型并行验证,延迟减半)、continuous batching(完成即返回、新请求补位)、prefill-decode 分离、**prompt caching**(重叠前缀只算一次,Anthropic 最长省 90% 成本 79% 延迟;Gemini 缓存 75 折)、KV cache 优化(Character.AI 组合三招降 20 倍)
5. **换 API 提供商 = 重新验收**:同一开源模型经不同服务商优化后质量有差异

## 验证案例
prompt caching 实测:首 token 延迟 11.5s → 2.4s;H100 满载一年 ≈ 7000 kWh(美国普通家庭年用电的 70%)——电力是扩张瓶颈,成本模型要算电。

## 适用信号
- 与客户谈 SLA 时(用 goodput);报价前做 token 成本模型;性能优化找不到方向时(先 roofline 判 compute-bound 还是 bandwidth-bound)
