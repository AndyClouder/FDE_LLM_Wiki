# 为学习付钱

## 核心打法
把生计绑在"发没发布"而非"学没学到 / 解没解决"上,是**政策级 Build Trap**;解法 = 分级注资 + 实验边界换失败安全。

## 操作步骤
1. **识别病态奖励**:某公司全员奖金挂 corporate scorecard——每年 12 月停下正事"ship whatever shit we can build in time that will check that box",1 月再花一个月拆烂代码,但 3 月奖金照发;销售过度承诺 roadmap 导致开发落后两年
2. **分级注资(VC 式)**:验证一步加一注——$50k 探索 → $250k 试产 → 数百万规模化;打破年度预算(反例:金融公司 CTO"年底不花完明年就扣",于是发现不该建也要建完——"That. Is. Insane.")
3. **给边界而非否决**:领导定实验上限($100k)与回滚预案,不逐项审批;Qwikster 分割未验证即全量推出,快速回滚后组织没有收紧创新,数年后自制剧大实验照做
4. **区分两种失败**:小而早、便宜、安静的失败(探索存在的意义)vs 十年慢烧式的失败(发布后从不度量,功能积灰)——"it is not a success if you fail and do not learn." / "Experimentation is the ultimate risk-management strategy."
5. **第一个实验选算术题**:OpenSky 首页实验两天验证无效,改用邮件 3 倍销量,算账省下 $250k——用小实验的算术成果换取组织的信任与安全空间
6. 个人级解法:用数据向上推(学员带初步数据证明产品不该建,产品日落、本人升职);销售侧:降佣金占比 + 留存纳入销售指标
7. **财务结构配套**([[Team Topologies]] 结论章,2026-08-20 补入):健康财务避免 CapEx/OpEx 割裂、大桶预算与项目死线;培训预算给团队而非个人福利(Auto Trader 全公司转 OpEx、无"IT 部门"概念)——与分级注资同一逻辑的资产负债表版本

## 适用信号
- 进场先看客户怎么发奖金——若奖金绑交付量,FDE 的一切方法论都会被这个变量吃掉([[人为错误的责任在系统]] 的组织版)
- FDE 的 [[Land-and-Expand与脚手架原则]] 与分级注资天然同构:每个阶段用数据换下一笔预算,而不是一单签死全年范围
