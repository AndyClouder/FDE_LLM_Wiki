# 学习瓶颈(learning bottleneck)

## 症状(怎么死)
商务/FDE 一人跑全部客户会议、回来转述——"我学到的 = 你们要做的",制造出以"客户说的"为王牌的独裁者;更极端:独自开会、笔记稀烂、从不与团队复盘,客户真相全部封存在一颗脑袋里。作者本人 bottleneck 到 CTO 离职:"We're never going to succeed if you keep changing what we're doing"——他学到的东西(大概)是真的,但没传达给团队就等于没有。

## 成因
- 症状话术:"你管产品就行,该知道的我会学" / "因为客户这么说!" / "我没空和人聊——我要写代码!"
- 客户学习被当成个人职责而非组织流程

## 解释概念
[[坑6-永久接口与能力不沉淀]] 与 [[坑7-沉淀缺失恶性循环]] 的认知层同族:知识不流转 = 能力不沉淀。

## 怎么堵
- **两人一组最佳**:一人专注笔记、一人专注对话,第二人当场纠坏问题;三人围审压迫感过强
- **所有做大决策的人(含技术决策者)至少出席部分会议**——亲听客户反应,团队才能互相纠偏
- **prep 与复盘制度化**:会前与团队定三大问题([[关键三问清单]]);会后过笔记、更新信念、也过 meta 层(哪些问题有效、漏了什么信号)
- **好笔记 = 小型知识库**:尽量记原话加引号(日后用于营销话术、压服怀疑的队友);索引卡一卡一条 + 符号速记(情绪 :) :( :|;生活五件套 ☇痛点/goal/☐obstacle/⤴变通/^背景;具体 ☑功能请求/＄预算/♀人名/☆follow-up);载体要求可排序、可合并、永久可检索
- **客户学习不可外包**:雇员带回坏消息("没人在乎")时你难以消化,lukewarm 信号更容易被雇员抹平;跑通可重复销售前,创始人/FDE 本人的耳朵必须在现场
- **走过场八信号自检**:你说得比对方多 / 对方在 compliment / 讲了点子却不知下一步 / 没笔记 / 没和团队看笔记 / 得到意外答案却没改变想法 / 没有一个问题让你害怕 / 说不清这场对话在回答哪个大问题
