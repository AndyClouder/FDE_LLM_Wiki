# Escaping the Build Trap

## 一句话内核
**以业务结果为导向,而不是产出物。**"The build trap is when organizations become stuck measuring their success by outputs rather than outcomes."(Build Trap = 组织用产出而非结果衡量成功)

## 全书逐章摘要(2026-08-20 全书精读)
> 虚构公司 Marquetly(在线营销教育平台)贯穿全文,故事均取自作者真实顾问经历。主线:Build Trap → 角色 → 战略 → 流程 → 组织 → Product-Led Organization。

- **Preface**:只培训 PM 个人无效——教过的 PM 数月后全部回潮(奖金绑定发版、经理看不见用户研究的价值);**困住的不只是 PM,而是整个组织**。四大组件:正确的 PM 角色 / 支持决策的战略 / 实验流程 / 政策文化与奖励
- **Part I(Ch1-5)价值与陷阱**:价值交换系统(客户问题被解决后才回流价值;2% 功能使用率案例;代理指标奖励);outputs vs outcomes("上个发布的东西谁回去迭代过?"只有 15-20% 举手);product/service/project 三分(项目思维误当产品管理);四种组织形态(sales-led 50-100 客户后必崩 / visionary-led 人走方向崩 / technology-led 酷东西没买家 / product-led);已知未知四象限
- **Part II(Ch6-9)PM 角色**:三个坏原型(**Mini-CEO** 90% 招聘启事这么写但 PM 无人事权靠影响力 / **Waiter** 接单员→Product Death Cycle / **Former Project Manager** 挥着日历的服务员);好 PM 案例 Meghan(房贷):业务目标→漏斗数据→流失者访谈→**concierge 手动实验完成率 +90%**→再产品化;"PM 是职业,PO 只是 Scrum 上的角色";PM 三级工作(tactical/strategic/operational)与晋升阶梯(APM→CPO);组队方式:按技术组件(登录 API 制造人造工作)/ 按功能 / **按价值流(TransferWise 按战略目标、Pandora 40 工程师 7000 万月活)**
- **Part III(Ch10-14)战略**:"Good strategy isn't a detailed plan. It's a framework that helps you make decisions.";**三大战略鸿沟**(Knowledge/Alignment/Effects,各有错误本能填法;Company B 明知错仍照建);战略框架 = operational + strategic 两层;Spotify DIBBs;战略部署 = 不同时间尺度的故事(Bloom;"不受限的团队最不敢动");四层阶梯 Vision→Strategic Intent→Initiative→Option;意图数量纪律(小公司 1 个、大组织 ≤3;5000 人 80 意图反例);Netflix 三级战略与杀掉 Project Griffin(Roku);Press Release 文档;组合四问(含"应该停掉什么")
- **Part IV(Ch15-19)流程**:**Product Kata 六问** + 四阶段(在错误的阶段用工具是最常见错误);"kill the bad ideas";成功指标(vanity→actionable 加时间分量;AARRR/HEART;**制衡指标对**;先行/滞后指标;先基线后目标);问题探索(generative vs evaluative 研究;custom dashboard 对话;女性导师 App 一周否掉已开发方案;**Marquetly 根因反转**——录入难真因是视频制作;research spies);方案探索三型(**Concierge / Wizard of Oz / Concept Testing**;MVP = "minimum amount of effort to learn";电商订阅邮件实验省 $100k+;GiveVision 手机+3D 眼镜;内部工具也是产品);建设与优化(North Star 文档 / Story Mapping / Cost of Delay;**"Version 2 is the biggest lie in software development"**;Definition of Done = 达标才算完;首发 60% 不达标继续 Kata)
- **Part V(Ch20-25)组织**:结果导向沟通节奏(**QBR/倡议评审/发布评审**三层例会;Living Roadmap;**Experiment→Alpha→Beta→GA** 四阶段;与销售 working agreement;Product Ops"成功的极致是自动化掉自己");奖励与激励(scorecard 年末"ship whatever shit"案例;降佣金+留存入销售指标);安全与学习(**分级注资 $50k→$250k→数百万**;两种失败;Qwikster 快速回滚不收紧创新;给边界而非否决;OpenSky 小实验省 $250k 换信任);预算(VC 式按确定性注资;反"年底不花完就扣");客户中心(John Deere 工程师下农场;经济困难期仍允许见客户是试金石);Kodak 大结局(2008 年做对了全部 discovery——三大需求全被 Instagram/Apple 做成,**做对研究救不了不为创新设置的组织**)
- **Afterword + 附录六问**:入行学谦逊("bad idea terminator; Data beats any opinion")、资深学战略框架、顾问学人格政治("把好员工放进无法成功的环境,是杀死其精神最快的方式");**六问诊断**(idea 谁提的/杀过什么产品/上次见客户/目标是什么/在做什么/PM 什么样)
