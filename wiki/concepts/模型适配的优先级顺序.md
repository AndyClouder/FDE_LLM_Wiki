# 模型适配的优先级顺序

## 一句话内核
**先穷尽 prompt 方案,再谈微调**——"finetuning is rarely the first thing you should attempt"。适配技术按介入深度排序:prompt 工程 / RAG / Agent(不改权重)→ 微调(改权重)。

## 展开
**为什么不先微调**:
- 微调需要:标注数据 + ML 人才 + 服务运维 + 持续维护(基础模型迭代速度可能快过你的微调收益)
- **经典教训**:抱怨"prompt 无效、必须微调"的团队,排查后普遍发现 prompt 实验做得少而不系统——指令不清、样例不贴实际数据、指标没定义。把 prompt 实验做扎实后,prompt 就够了
- **BloombergGPT 教训**:50B 参数、130 万 A100 小时(约 $1.3-2.6M 计算成本)的金融专用模型,发布同月被通用 GPT-4-0314 在金融基准上全面超越——通用模型变强会吞掉专用模型的优势
- 微调还可能损害其他任务的表现(alignment tax),多任务场景需全量微调、分模型或模型合并

**什么时候才微调**:特定输出结构(JSON/YAML)、小模型蒸馏(Grammarly:82K 样本微调的 Flan-T5 比 60 倍大的 GPT-3 变体更好)、私有化部署需求、偏见矫正。

**失败模式诊断维度**(Ch7 全书精读补充,本章最重要框架):先问失败是**信息型**还是**行为型**——
- 信息型(缺私有信息/知识过时 → 输出**事实错**)→ 用 RAG
- 行为型(事实对但无关/格式坏/风格错)→ 用微调
- **"finetuning is for form, and RAG is for facts."**
- Ovadia et al. 实验佐证:时事问答上 base+RAG 全面胜过 finetuned,也胜过 finetuned+RAG(57% 的情况)——微调灌知识反而伤其他能力;Llama 3.1 原则:post-training 应让模型 "know what it knows" 而非灌知识
- 两者兼有问题 → 先做 RAG(更易)

**适配五步顺序**:prompt → prompt 加例子(1-50 个)→ 接数据源(先 term-based RAG/BM25)→ 按失败模式选 embedding RAG(信息型)或微调(行为型)→ 双管齐下。

**语言不平等警示**(Ch2,2026-08-20 第二轮补入):Common Crawl 英语占 45.88%(第二名俄语的近 8 倍)→ 低资源语言系统性劣势:同一数学题英文可解、Burmese/Amharic 全错;tokenization 效率使 Burmese 同内容比英文**贵 10 倍慢 10 倍**;NewsGuard 测试 ChatGPT 中文 7/7 产假信息、英文 6/7 拒绝——**非英语交付场景必须实测目标语言的成本与质量,不能拿英文基准外推**。

**选型漏斗**(Ch1+Ch7 综合):用例评估 → build vs buy → 现成模型评测(能力越强,自建工作越少)→ prompt 优先 → RAG 补上下文 → 仍不达标才微调。
