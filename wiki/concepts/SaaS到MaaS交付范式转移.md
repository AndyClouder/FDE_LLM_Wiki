# SaaS → MaaS 交付范式转移

## 一句话内核
AI Agent 时代客户要的不是模型和 API,而是"**能把事情做完的流程**"——交付范式从卖席位的 SaaS 转向卖成果的 MaaS(Model-as-a-Service / Mission-as-a-Service),这是 FDE 模式现在成立的底层经济逻辑。

## 展开
- **SaaS 逻辑**:PMF 后统一产品规模化、边际成本趋零——适合 CRM/HR/财务/协同等**标准场景**
- **MaaS 逻辑**:一个能干活的 Agent 需要:数据接入 / 权限体系 / 流程适配 / 合规审计 / 异常处理 / 人工兜底——高度贴合业务,传统上只有定制开发能做到
- **为什么现在经济上成立**:AI 降了原型/编排/适配成本,**使"原本不划算的定制化重新具备经济性"**——Agent 介于标准 SaaS 与传统定制之间
- **收入结构变化**:场景跑通带来持续模型调用与工具调用,收入从"卖席位"转向"**持续使用**"——FDE 投入不是前期交付成本,而是在**放大客户生命周期价值(LTV)**
- 商业闭环证据:头部客户在工具采购外**单独为 FDE 陪跑付费,金额百万级到五百万级**;收入结构 = 服务包与培训认证(短期)+ 持续消耗(长期引擎);席位费只是入口(见 [[腾讯云FDE实践样本]])
