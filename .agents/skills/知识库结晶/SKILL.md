# 知识库结晶(CRYSTALLIZE)

把一次工作过程蒸馏成可复用的资产:结晶页 + 可选的新 wiki 页面。
**规则以根目录 `AGENTS.md` 为准**。探索过程本身就是源——这是 LLM Wiki v2 的 crystallization 原则。

## 触发条件(任一)
1. 一次有价值的会话结束(完成摄取/解决了重要问题/做出关键决策)
2. QUERY 产生高质量回答(推理链完整、用户认可)
3. 用户明说"结晶一下"

## 操作步骤

### 1. 写结晶页
- 路径:`episodic/YYYY-MM-DD-主题.md`(type: digest)
- 五段结构(必填全):
  1. **当天的问题**:这次会话要解决什么
  2. **做了什么**:动作序列,压缩到可复盘粒度
  3. **关键发现/决策**:包括"哪个判断被证伪"
  4. **教训(可复用)**:写成独立成立的一句话,不依赖本次上下文
  5. **待办**:下次会话的自然起点
- frontmatter 引用本次会话真正用到的源(`[[源名]]`)

### 2. 判断晋升(不是所有教训都进 wiki)
- 教训满足:可独立成立 + 未来会反复用到 → 晋升为 wiki 页
  - 新坑位 → `wiki/pitfalls/`
  - 新概念 → `wiki/concepts/`(status: working,置信度 0.6)
  - 新打法 → `wiki/practices/`
- **已有页面的强化**:本次会话验证了某打法/概念 → 走强化(source_count +1、last_confirmed 更新)
- 只对本次有意义、不构成通用知识的 → 留在结晶页里,不晋升

### 3. 收尾
- 更新 `graph.md`(新实体/边;结晶页本身不进图谱,除非产生新实体)
- 更新 `index.md`(episodic 列表 + 统计"结晶"计数)
- `changelog.md` 记一行

## 踩坑点(gotchas)

- **结晶不是流水账**:五段里的"做了什么"要压缩;价值在"关键发现"和"教训"两段
- **教训必须脱离上下文可读**:三个月后重读,不需要回忆本次会话就能用
- **晋升要克制**:wiki 页面数不是 KPI;一无所获的会话不硬凑结晶
- 结晶页文件名带中文主题时,引用用 `episodic/文件名.md` 相对路径(Obsidian 链接兼容)
- 记得更新 index.md 的"结晶 N"统计数字(容易漏)

## 可容错

- 会话信息不全(中途加入):结晶页"做了什么"标注覆盖范围,不补猜
- 晋升页面证据不足:先入 inbox/ 作为观察,下次强化后再晋升

## 可扩展

- 定期(如每周)回顾 episodic/:多篇结晶中的重复教训 = 该晋升的信号
- QUERY 高质量回答的回流阈值:推理链完整 + 用户明确认可,两者取其一即可提议
