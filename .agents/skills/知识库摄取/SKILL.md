# 知识库摄取(INGEST)

把一份原始资料转化为知识库资产:源卡 + 声明页面 + 图谱关系 + 审计记录。
**动手前先读知识库根目录的 `AGENTS.md`**(宪法:页面模板 §3、置信度规则 §4、实体关系 §5)。本技能只定义操作程序。

## 操作步骤

### 0. 扫描队列
- 列出 `inbox/` 全部文件,对照 `wiki/sources/` 源卡:没有源卡的资料先建卡(`ingestion: pending`)
- 与用户确认本次处理哪些(或按 index.md 待摄取清单的优先级)

### 1. 建源卡
- `wiki/sources/<源名>.md`,frontmatter 按 AGENTS.md §3;`path` 指向 inbox 内文件
- 登记作者/格式/出版信息;一句话内核(此时可来自目录或快速浏览)

### 2. 脱敏(强制,先于一切内容处理)
- 剥除 API key、token、密码、未公开个人信息;发现即弃,不写入任何页面

### 3. 文本提取(按格式)
- **PDF**:`pdftotext -enc UTF-8 <文件> <输出.txt>`(输出放 `.zcode-tmp/`,用完删)
- **EPUB**:python `zipfile` 解包 + 正则剥 HTML 标签(h1-h6→`##`、p/div/li→换行)
- **MD/剪藏**:直接读
- **网页**:WebFetch 或用户已存的剪藏

### 4. 定位相关章节(不要通读全本)
- 先读目录(TOC),选 2-4 个与库主题相关的章节:该书的源卡"堵哪个坑"指向的页面族
- 大文件用 `sed -n 'A,Bp'` 分段取,或 grep 定位关键词行号

### 5. 提取声明 → 强化或新建
- 每条**可独立成立的判断**落页:
  - **已有页面**:走强化 —— `source_count` +1、`last_confirmed`=今天、置信度 +0.05(规则见 AGENTS.md §4)、正文加"原书确认"小节引用原文关键句
  - **没有页面**:新建(概念/坑位/打法按 AGENTS.md §3 模板),初值 confidence: 单源 0.6
- 与已有声明**冲突**:走 AGENTS.md §7 矛盾处理,提议 supersession,记 changelog

### 6. 收尾(缺一不可)
- 源卡升级 `ingestion: full`,补章节摘要与"已沉淀页面"列表
- 更新 `graph.md`(实体表 + 关系表,边带依据和置信度)
- 更新 `index.md`(目录、统计行、待办勾选)
- `changelog.md` 记一行

## 踩坑点(gotchas,实跑验证)

- **中文/特殊字符文件名会让 mingw64 工具链(pdftotext 等)乱码**(`系统之美(德内拉•梅多斯)…pdf` 实测踩中):先用 python `shutil.copy` 复制为 ASCII 临时名(如 `.zcode-tmp/tis.pdf`)再提取,python 的 Windows Unicode API 不受影响
- **EPUB 就是 zip + XHTML**,不需要专用工具;转换时把 h1-h6 映射成 `##` 标题便于导航
- **Edit 已有文件时,old_string 若选整段,新内容必须保留原段落的全部有效信息**——本库曾两次把 changelog/印证段落整段覆盖丢失;宁可分两次小编辑
- **Bash 输出超过 ~30KB 会转存 persisted-output 文件**,用 Read 分段读,别硬 cat
- **每书精读 2-4 个相关章节比通读全本高效且足够负责**;未读部分在源卡如实标注精读范围,不冒充全读
- 书中细节分主题归入对应页面,不要在源卡里堆全文摘要

## 可容错

- 提取/读取中断:已建源卡保留 `pending` 状态,下次续跑
- 某章节提取质量差(乱码/扫描版):源卡标注"该部分不可提取",不猜内容
- 任何一步失败,已完成的步骤不回滚,记 changelog 说明断点

## 可扩展

- 新页面类型/关系类型:先改 AGENTS.md §3/§5,再用
- 多份资料交叉印证同一页面:source_count 累加,置信度按 §4 重算
